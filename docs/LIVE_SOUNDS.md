# Live sounds page

Open `http://localhost:8000/live-sounds.html` after starting both services with `python run_servers.py --mock` or the real Ganglion port. The page connects to the existing EEG WebSocket on `localhost:8765`. It does not load or play audio.

1. Keep the Test page closed while recording. The EEG service has one global stream and global start/stop state.
2. Connect EEG. This starts the EEG stream so the embedded electrode quality box can show each channel's RMS (μV) and Good/OK/Poor status before recording. Wait for the ready message and check contact quality.
3. Start and stop a quiet baseline segment.
4. Describe sound 1, start it on your external device when you click **Start sound 1**, and stop the segment when the sound ends. Enter a new description and repeat for sound 2, sound 3, and so on. All sound segments share the same baseline and session export.
5. Export the full JSON for a durable copy of every reading. Export the summary CSV for analysis software: it contains one row per baseline or sound segment, including notes, reading counts, mean relative band power, and each sound's percentage-point difference from that session's baseline. You can create a new session and record a new baseline without disconnecting EEG.

The live chart shows the most recent 90 relative band power readings. The table reports mean alpha and percentage-point changes in all five relative bands compared with the first baseline. These are descriptive observations, not causal estimates. The EEG service sends rolling band estimates and quality metrics, not raw waveform samples. A segment stops at 3,600 readings to limit browser storage use. Saved segments remain in this browser's local storage until a new session is started or browser data is cleared; they do not enter the existing Test/Analyze database. Full JSON is now compact (one line) but contains the same readings. For JSON files exported by earlier versions, `python3 scripts/live_sounds_to_csv.py file1.json file2.json --output summary.csv --windows-output windows.csv --window-seconds 10` makes both a segment table and a time-window table without changing the source files. Time windows show within-sound trends; they are repeated measurements within the same sound segment, not additional independent tests.
